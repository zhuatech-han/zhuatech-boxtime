## 首次部署

要求Docker Compose v2、Python3.10+；镜像构建提供Java21/Maven3.9和Node24.19，宿主机无需安装Java。先运行python3 scripts/init-env.py，再docker compose up -d --build。等待mysql、backend、frontend全部healthy；访问http://127.0.0.1:8126/actuator/health应为UP。初始化账号admin，密码从本地.env读取。不要把口令贴到日志或聊天。

## 配置

.env.example列必需DATABASE_PASSWORD、MYSQL_ROOT_PASSWORD、ADMIN_PASSWORD，和WEB_PORT、BIND_ADDRESS、COOKIE_SECURE。数据库zhuatech_boxtime，内部用户boxtime，容器名由Compose项目隔离。后端配置可直接通过环境DATABASE_URL、DATABASE_CATALOG、DATABASE_USER改变自建环境，须同时匹配迁移数据库；默认Compose内部配置已就绪，未经授权勿修改正式凭证或生产配置。

HTTPS公网场景配置TLS代理、域名和COOKIE_SECURE=true；默认仅本机HTTP用于学习。健康检查经前端转发；数据库和后端无宿主机公开端口。所有密码不能为空。

## 升级与迁移

先备份并验证能恢复，取新源码构建，再docker compose up -d --build。保留mysql-data卷；Flyway按新版本增量迁移。已有V1/V2不可修改。回退代码并不自动回退数据库，不能盲目替换卷。改变ADMIN_PASSWORD不会重置既有账号。

## 备份与恢复

仅在隔离验收项目演练以下示例。备份文件包含敏感业务，目录private-backups已忽略，设为0700，文件0600。终端内密码取自容器环境，不输出：

```bash
mkdir -p private-backups
chmod 700 private-backups
docker compose exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --no-tablespaces --set-gtid-purged=OFF zhuatech_boxtime' > private-backups/boxtime.sql
chmod 600 private-backups/boxtime.sql
```

恢复应使用新的独立Compose项目和空卷，先只启动mysql，待健康后导入再启动应用。例如在本地验证，WEB_PORT=18126创建boxtime-restore：

```bash
WEB_PORT=18126 docker compose -p boxtime-restore up -d mysql
# 等mysql healthy后导入
docker compose -p boxtime-restore exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" zhuatech_boxtime' < private-backups/boxtime.sql
WEB_PORT=18126 docker compose -p boxtime-restore up -d backend frontend
TEST_URL=http://127.0.0.1:18126 python3 scripts/smoke.py --verify
```

验收状态比对文件来自同一合成测试数据库；不复制实际客户数据。验证后仅清理本次boxtime-restore/boxtime-check资源；不能全局清理Docker或其他项目。日常停止docker compose down保留卷，down -v会删除数据。

## 排障

用docker compose ps和docker compose logs --tail=100 backend检查健康与启动，保护日志中私有配置。数据库结构不匹配先核对迁移与数据库名，不自动删库。构建失败读取测试结果修复，不允许跳过测试。端口占用则选独立WEB_PORT，不停止其他服务。
